agent-x402

Pay per API call in USDC on Base — with a spend policy a prompt injection cannot bypass.

An agent can buy an API call without an account. The same agent can also spend the wallet. This client pays, the policy decides whether it may, and the server settles USDC to an address you control.

View on GitHub npm README

Install

npm install agent-x402
ax402 new
ax402 quote https://pay.example.com/v1/resource
ax402 pay https://pay.example.com/v1/resource

Node.js 20+. The buyer wallet is created in ~/.config/agent-x402/wallet.json (mode 600). Fund that address with USDC on Base. The private key is never printed.

What it does

x402 v2, exact schemeEIP-3009 transferWithAuthorization for USDC on Base mainnet (eip155:8453).
Spend policyDaily cap, per-request cap, payment count, payee allow-list, blocked contracts, per-network cap. A failed call does not count.
Policy outside the modelThe rules run in code before anything is signed. Two in-flight payments share one cap.
Sellerax402-serve quotes a price and settles through Coinbase's facilitator. The server holds no signing key.

Get paid

  1. Set X402_PAY_TO to a Base address you control. The published donation address is 0x8aC6a229f254980CCd3Dd35CF5E1B7c08880B40E.
  2. Create a Coinbase Developer Platform API key. Put CDP_API_KEY_ID and CDP_API_KEY_SECRET in the server environment only.
  3. Run ax402-serve with X402_FACILITATOR_URL=https://api.cdp.coinbase.com/platform/v2/x402, X402_PRICE_USD, and X402_PUBLIC_URL.
  4. Check GET /health reports settlement: facilitator, then pay the route once with a small amount and confirm GET /stats plus the USDC balance.
  5. To publish the client: add an npm Automation token as the NPM_TOKEN Actions secret, then push the tag v0.2.0.

Until the facilitator is configured, the server quotes a price and does not deliver the resource. No payment is submitted.

How a call works

  1. The client requests the URL. A 402 comes back with the price, the network, and the payee.
  2. The policy checks caps and allow-lists before the wallet signs.
  3. The client signs EIP-3009 and retries with PAYMENT-SIGNATURE.
  4. The server verifies the signature, runs the handler, then asks the facilitator to settle. Revenue is USDC at X402_PAY_TO.
